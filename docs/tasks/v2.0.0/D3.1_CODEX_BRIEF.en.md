## 3. Public data, exact mathematical contract and validation

Prefer:
- models/include/probspan_models/standardize.h
- models/src/standardize.c
- models/tests/standardize.c and standardize_probe.c
- new independent Fraction qualification script and evidence files under models/tests/
- only necessary edits to models/CMakeLists.txt, installed consumer, install matrix, CI and docs.

Choose consistent public ps2_ identifiers and explicit typed structs/enums. Each stratum supplies a finite nonnegative double target_weight, explicit known/unknown support flag, and a double conditional_risk when known. Known risk is finite in [0,1]. The function borrows input only during the call and stores no pointers. Output is caller-owned and must not overlap input.

Count zero = EMPTY; 1 through 1024 supported; above 1024 = UNSUPPORTED. Null pointer, unknown flag, NaN/infinite/negative weight, or invalid known conditional risk = INVALID_ARGUMENT. Define and test exact precedence when multiple faults coexist. Decide and document whether an unknown risk's unused bits may be unspecified. Define consistent semantics for -0 weight and zero-weight known risk. There must be positive total target weight. Invalid/unsupported weight normalization must have an honest documented result distinct from numerical inability to decide.

Let w_i and p_i denote exact real values of their binary64 encodings, and let W=sum_i w_i as an exact mathematical sum. Input weight normalization is acceptable iff the CLOSED mathematical inequality |W-1| <= 1/10^12 holds, where the policy threshold is the exact decimal rational, NOT the nearest binary64 representation of 1e-12. Reject genuinely out-of-policy input; classify uncertainty NUMERICAL_FAILURE rather than falsely calling a borderline-valid vector invalid.

On accepted input, define A=sum_{known} w_i*p_i and U=sum_{unknown} w_i, both with exact input-value semantics:
- If U is exactly zero: the target risk point is R=A/W; return identified-point state with the honest real-value-to-binary64 representation diagnostic/enclosure.
- If U>0: the sharp identification interval is [L,H] = [A/W,(A+U)/W]. Return partial-identification state, no accessible point. One completion assigns unknown risks all zero and attains L; another assigns all one and attains H.
- A zero-weight unknown stratum cannot change support or risk; a tiny strictly positive unknown weight MUST preserve partial-identification status even if W normalization would underflow in a naive double calculation.
- Do not silently remove unknown groups then renormalize known groups. Do not treat missing conditional risk as zero, even where the output's encoded width is tiny.
- No confidence/credible interval, variance, validity of sampling, causal transport, or joint estimated-weight uncertainty is calculated. The caller asserts comparable event definitions, horizons, fixed weights and exhaustive disjoint target strata. B-E003 shows that random weights estimated with risks can require covariance; this fixed-weight function does not claim to solve that issue.

All unsuccessful calls must leave the entire output byte representation unchanged. Validate and compute locally; publish only on success. No heap, I/O, clock, RNG or hidden mutable global state. Keep output data finite, within [0,1], ordered, and exact structural 0/1 with positive zero.

## 4. Non-negotiable numeric proof and encoded-output contract

This operation has an unusually strict D1 precision contract. Ordinary compensated double arithmetic plus a tolerance is NOT an acceptable substitute for an exact numeric policy decision or outward sharp bounds.

A. Exact W and policy test:
Use a proven enclosure for W which can decide only if it is fully inside or outside the closed policy range. On overlap use exact dyadic accumulation and rational comparison with 1+/-1/10^12, or return NUMERICAL_FAILURE and preserve output. Document the finite bit width, operations and bounded work. Never compare rounded fabs(double_W-1) against a double approximation to 1e-12 as if this proves the exact mathematical inequality.

B. Exact/conservatively enclosed A, U and division:
Weights and risks can include minimum positive binary64 subnormals, with a weight*risk exact product exponent as low as -2148. Account for all 1024 terms and possible cancellation/normalization. Use a bounded fixed-size dyadic/integer accumulator and explicitly directed binary64 division, OR prove an equally rigorous enclosure all the way through result encoding. An exact Fraction reference is required; do not convert intermediate products to ordinary double and discard positives.

The accepted result must return the pair of immediately neighboring binary64 encodings enclosing the exact real value, or the identical single encoding if exactly representable. For partial identification, the public lower bound must round OUTWARD DOWN and the upper must round OUTWARD UP. The sharp set must never be narrowed. For strictly positive exact R between 0 and the smallest subnormal eta, an honest outward enclosure is [0,eta] and any zero point encoding must carry representation-loss status. A subnormal positive unknown weight remains positive support even if the rounded upper/lower values coincide. Conservative but needlessly loose [0,1] is not a substitute for the adjacent-encoding contract.

The finite implementation must document capacity, integer sign/carry, bit shifts, exponent limits, stack/workspace and time bounds. No integer overflow, undefined shift, unbounded loop, unsupported external multiprecision runtime, or excessive stack use. If an otherwise allowed input cannot be certified with the chosen resources, return NUMERICAL_FAILURE unchanged and disclose its exact scope; do not silently shrink the 1..1024 domain. Avoid claiming universal relative-error guarantees near zero.

C. Required corner cases:
- All known; zero-weight unknown; unknown positive; all unknown; one known or unknown unit weight; risks 0 and 1.
- Weights .8 and .2 with risks .1 and .4 yield approximately .16, while replacing the second risk by unknown yields approximately [.08,.28], computed from the EXACT supplied encodings rather than idealized exact decimal fractions.
- +-0 weights, eta=2^-1074, minimum normal 2^-1022, nextafter(1,0), nextafter(1,+infinity), near 1e-12 policy boundary, highly unbalanced weights and exact positive products below eta.
- Stratum permutation must not change mathematically exact result or certified output encodings.
- 1024 strata and invalid/null input must avoid overflow and leave output unchanged.
- Sharp completion worlds (every unknown risk 0 versus 1) must attain the exact reference bounds.

Do not introduce new public F001/F002 APIs, rewrite prior numerical solvers or change Models ABI number unless a separately reviewed, justified compatibility decision requires it.
