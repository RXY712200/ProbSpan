## 1. Deliver exactly one F004 mathematical capability

Implement the narrow fixed-origin aggregated competing-risk Aalen–Johansen cumulative-incidence operation in the separately installed C11 ProbSpanModels 2.0.0 package.

Mathematical output through a requested inclusive integer horizon h:
- Overall event-free survival S(h) = product over event times t<=h of (1 - (d_target(t)+d_other(t))/Y(t)).
- Target-cause cumulative incidence F_target(h) = sum over t<=h of S(t-) * d_target(t)/Y(t).
- An integer-derived follow-up/support diagnostic and any necessary representation/precision diagnostics; not a confidence interval, cumulative hazard, Bayesian posterior, predictive density, or 1-Kaplan–Meier with competing events censored.

Y(t) counts the risk set *before* same-tick target events, competing terminal events, AND loss to follow-up. Both terminal causes at the same tick use this same Y(t). Remove all counted exits (target, competing and censored) from the integer risk set for the next tick. Censoring alone does not decrease S; competing terminal events DO decrease event-free S. Never silently treat terminal competing events as censoring, and never reconstruct a risk set from anonymous binomial event/nonevent totals.

Implement finite point-risk arithmetic, support and representation diagnostics ONLY. NO D3.3 scoring, F006 borrowing, parametric hazard fitting, delayed entry, reentry, recurrent events, multi-state transitions, confidence intervals, censoring weights, field correction, caller-side data provenance, database/file ingestion, or source-to-population transfer. Do not revise accepted F001/F002/F003 numerical solvers or CMake package identity. Legacy ProbSpan 1.1.0 must remain byte-identical in protected files.

D1's ps2_cumulative_incidence(rows, length, horizon, out) signature is a DESIGN SKETCH, but the actual operation also requires initial cohort size and an explicit observable follow-up cutoff. Define a small self-contained C11 request/cohort structure carrying initial_count, observed_through_tick, row pointer/length and requested horizon, or a similarly explicit typed signature that does not hide either requirement in global state. Keep the public ps2_cumulative_incidence identifier and ps2_ prefix, with C++ linkage guards, fixed-width counts, no heap, no I/O and no hidden mutable state. Treat any material deviation from the D1 scientific input/output contract as a stop-and-report owner decision, not a quiet edit to the approved plan.

A row has a strictly increasing integer tick, count of target-cause terminal events, count of other terminal events, and count lost to follow-up at the tick. All counts are unsigned 64-bit, with explicit units described in docs. Initial cohort size is nonzero and at most 2^53, row length <= 1,000,000. At n0=0 return EMPTY. For length=0 with nonzero n0 and genuine observed follow-up through h, return S=1, F=0; do not synthesize unseen events. Caller asserts common origin; no staggered enrollment or individuals returning to a risk set.

A horizon beyond the caller's observed_through_tick is UNSUPPORTED_HORIZON, not a zero-risk extrapolation. Rows beyond the observation cutoff are inconsistent input. Rows after the requested horizon may exist for validation but MUST NOT affect the horizon result. Any event-time tick <= horizon contributes to the estimate (inclusive horizon). Define whether tick zero is permitted relative to origin and how an empty observed interval is represented; choose a narrow consistent convention preserving D1's horizon semantics and test it explicitly. Reject duplicate and nonascending ticks. Reject a row when d_target+d_other+d_censored exceeds current integer Y, using overflow-safe integer subtraction/checks rather than summing three uint64 counts first.

Risk-set evolution:
- integer Y starts at n0;
- at row tick t, compute cause increments using the same Y BEFORE any exits that tick;
- survival factor uses d_all=d_target+d_other (NOT censored count);
- next risk set = Y-d_target-d_other-d_censored.
- If all at-risk people are censored at t, and the requested horizon is later than t while mathematical S remains positive, report UNSUPPORTED_HORIZON even if observed_through_tick extends past t; never output an apparently observed flat risk beyond the loss of support.
- If S has become structurally exactly zero because every remaining at-risk individual had a terminal event (no survivors), subsequent hazard contributions are zero and F is constant. A horizon later than the last terminal event can remain supported provided the observation-cutoff contract is met. Do NOT infer structural S=0 merely because an encoded floating S underflowed.
- Define and test the exact t==h boundary after complete censoring: t itself has an observed risk set for the tick, but t+1 no longer does.
- If Y becomes zero at or after a row, no later row may report positive exits or resurrect people. A subsequent all-zero/no-op row should have one documented consistent validation outcome; do not silently create follow-up support.
- Explicitly explain how the API distinguishes lack of risk-set support, end of observation, events completed, and mathematical zero versus representation zero. Do not claim missingness-at-random or censoring independence can be checked by the library.

Strong validation: null pointers for required objects; rows pointer null only when length zero; unsupported n0/row length; invalid ordering; overflow-prone count exit sum; horizon and observed cutoff; empty cohort; wrongly stated evidence domain. Distinguish INVALID_ARGUMENT, EMPTY, UNSUPPORTED, UNSUPPORTED_HORIZON, NUMERICAL_FAILURE and OK where meaningful. Define exact error precedence and enforce failure-atomic output (all output bytes unchanged for ANY failure), including unsupported horizon discovered during traversal. Keep output and input nonoverlapping and caller-owned.

Scientific contract assumes independent observation units, defined time origin, same endpoint/horizon, non-informative loss to follow-up relative to potential failure type/time, and trustworthy mutually exclusive terminal cause classifications. The calculator does not validate these assumptions. It emits the conditional point estimator, not guaranteed field truth, coverage, or 1-KM.

## 4. Mathematical examples and sharp negative controls

Document and test exact small examples using independent rational expectations:

- 10 initially at risk; tick1 target=2, competing=3, lost=0: S=.5, F=.2. At next tick, Y=5 and target=1, competing=0, lost=0: final S=.4, F=.3. A competing-censored 1-KM calculation would give .36, WRONG estimand.
- The Phase B B-E004 two-period hazard example: cause 1/other at t1 .10/.20, then cause1 at t2 .20 conditional on surviving t1, gives true competing-risk CIF .24; censoring the competing event in a 1-KM estimator gives .28. This is a population mechanism counterexample, distinct from the 10-person integer example.
- Censoring before a later row changes integer Y; correct survival and CIF use at-risk survivors at event time. Simultaneous target, competing, censored counts must share pre-removal Y.
- No target cause with competing events: F=0, S may be less than 1.
- All terminal events: S=0 exactly, future h remains flat; all lost: support exhausted and later h UNSUPPORTED_HORIZON.
- No-event/no-censor full follow-up to h: S=1, F=0.
- Two different loss-to-follow-up mechanisms can yield the same observed risk-set counts but different latent target risks; use the informative-censoring counterexample from Phase B to show no field-validity certification is possible.
- Reject duplicate ticks, nonmonotone times, oversized exits (including near UINT64_MAX), absent cutoff/horizon mismatch, zero-risk-set positive exit and delayed entry/reentry attempts when representable.
- Explicitly enumerate test cases with horizon exactly at versus just before/after a row tick and with rows after h, to prevent off-by-one and wrong extrapolation.

## 5. Numerical method, proof and qualification gate

The bound must remain valid across m<=10^6; no universal tail-relative error promise follows. If the implementation uses a different operation path or has libm/compensation effects, establish a matching provable bound or tighter independent per-input enclosure and document the derivation. Merely quoting D1's formula and passing floating tests is NOT an acceptance proof.

Keep risk-set/depletion status computed ONLY from exact integer counts. Preserve monotonicity and F+S<=1 mathematically; account for floating representation and any returned error envelope separately.
