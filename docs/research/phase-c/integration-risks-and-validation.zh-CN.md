## 迁移与验证矩阵

- **兼容新增**。可选工具的新结果及显式快照格式能独立交付。旧调用仅依赖既有公开入口，无新增运行依赖。移除外部适配后可返回直接调用的基线。应用快照格式独立于模型版本；不可解释的旧版本可只显示当时原结果。
- **内部替换**。同域叶节点须经独立参考，阈值状态、readiness、解析正零、NO_HISTORY 的字段忽略及错误先后需回归。新消费者若需要不同误差单位或更广域，保留独立算法。性能和资源预算由实际需求/设备测量。
- **需单独授权的破坏性变更**。扩公共记录、改枚举语义、改变支持环境或 readiness 可能破坏消费者。若存在正当需求，保留旧轨、按明确字段迁移或拒绝，旧记录不由新模型改写。静态 ABI 不意味着跨编译器结构体字节相同。
- **工程与科学分别验收**。保护旧 C 输出和安装消费者；可选适配比较端到端已批准样本经其与直连旧 API 一致，测试错版本、后端数值失败及合法弃权。部件数值试验需独立 oracle 和相关平台。真实端点按簇和时间留出，评估误纳/误拒、全请求代价与置信范围。固定夹具与 CTest 不检验现场适用性。 [测试](../../TESTING.md) · [B 外证](../phase-b/external-evidence-and-limitations.zh-CN.md)

反方审查削弱了“先通用共享”的理由。如果唯一任务的应用已有成熟快照/身份工具，额外适配只重复责任；无实证就保持现状。若现有 Preview 能满足实际约束，也无需新增公共 C 接口。数值核的第二消费者与设备试点不存在必然先后。
