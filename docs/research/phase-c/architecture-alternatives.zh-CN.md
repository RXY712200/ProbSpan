## 哪个路径在何种情况下更合适

当前采用**现状作为默认保留路径**。如果所有者能提供一条可复验的固定端点任务，首选比较受限的外部证据适配与直接 caller baseline。它解决的是“可数但不该数”的重复开销，适配可一键移除且不用 C 版本/ABI 改动。只有实际测到更低的误纳/误拒、可接受的弃权/延时和较低的维护成本时，才认为它胜过现状。优先以本项目已有 Preview 执行对照；没有实证时不复制它，也不把 Preview 升级成承诺。

最有吸引力的否定意见是：适配器会重复应用已具备的快照/身份工具，且它本身无法证明领域真实。若重复价值不足，保留现状和可读参考即可。保守 C 扩展仅在独立受益和复用同一数学内核已经证实后重议。广集成库对需要一体训练/校准的真实群体可能合适，但把共同词汇包装成统一 `fit/predict` 会直接掩盖端点、证据、依赖及区间目标差异，当前证明和用户证据无法支付其维护成本。 [B-E002](../phase-b/experiments-and-results.zh-CN.md#b-e002) · [B-E007](../phase-b/experiments-and-results.zh-CN.md#b-e007) · [现行范围](../../ORIGIN_AND_SCOPE.md)

用同一反例比较：带删失的 100 小时设备任务在基线由调用方检查而拒绝输入；外部适配能给可溯源的拒绝和风险集交接；单纯扩大二项数学核仍不能恢复失访数据；宽库若另有生存模块也必须接受原始时序而不能从历史计数推回。这个差别是责任/信息优势，与某个后验 RMSE 的数值无关。 [B-E004](../phase-b/experiments-and-results.zh-CN.md#b-e004)
