# Preview、RC 与 Stable 验收

D1 的可信设计基线采用独立接受后的 PR 提交、实际范围及授权记录。Preview 文档用提交标识及清单说明已实施、未实现和临时合同。按功能更新 API/兼容、构建与四篇中文指南的相关块，保留历史基线。推进以可用能力和已接受证据为单位。

| 检查点 | 可观察门槛 | 停止条件 |
|---|---|---|
| 基础 Preview 候选 | D2.1–3 接受。可从干净前缀运行二项区间、先验更新和预测批次，数值与历史兼容矩阵通过；读者能标识置信与预测对象 | 缺独立基准、失败合同或旧消费者失败 |
| 扩展 Preview 候选 | D3.1–3 接受。三类新增操作可独立重跑，缺支持、被截尾、分母反转等反例均可证；提供实际使用文档 | 静默填未知、截尾错误、评价分母混用或功能只有示例 |
| RC | D4.1–2 接受，重新由最后可信 v1/v2 文档、Preview 快照和最终树追踪各源码差异；冻结表面、参考、支持边界、安装分发及迁移。以精确 SHA 日志复核五平台和两包消费者 | 有实际合同分歧、数值失败未受控、发布资产或证据树不一致 |
| Stable | D5.1 独立接受，D5.2 另授权准确 SHA、tag、公开分类和资产。发行后回读 Git 对象、版本/分类、可访问档案并校验内容 | tag 已存在且不符，远端树漂移，测试缺失或独立接受缺失 |

Preview 和 RC 发版次数随可评审的变化与实质风险而定。每个发布动作需要独立授权。合并、发布和回读分别验证。参考 [现行发布说明](../../RELEASING.md)。
