# Frozen reference vectors

`v1_vectors.jsonl` is generated by `generate.py` from the author's `probability-calibration-tool` commit `a581f84ccd217ed45789b3566347255f56ffbeac`. The generator refuses another reference HEAD. It calls the frozen core functions and, for exposure and revision cases, the frozen `RoundService` with a temporary database, fixed clock, and deterministic IDs. The database is development tooling only; the C library has no persistence dependency.

From a checkout of the frozen reference, with its locked Python dependencies installed:

```sh
uv run python /path/to/ProbSpan/oracle/generate.py --reference-root .
uv run python /path/to/ProbSpan/oracle/generate.py --reference-root . --check
```

Each JSON Lines record identifies a behavior group and case, the inputs, and the observed output. `null` represents unavailable results. Enum strings, flags, integers, raw values, and structure are exact. `numerical_policy.json` defines tolerances for later C parity checks; the generator's `--check` compares the committed reference text byte for byte in the locked reference environment. The current C smoke test verifies only that the scaffold links and runs.

The source and tests agree on the behavior sampled here. In particular, the subjective width is the frozen piecewise function, and a first exposure during recalculation does not retroactively compromise that same revision. These cases should not be replaced with a newly inferred model.
